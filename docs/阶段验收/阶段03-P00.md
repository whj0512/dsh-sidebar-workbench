## 实际交付

| 范围 | 当前行为 |
| --- | --- |
| P00 材料选择 | 两个路径框铺满可用宽度，输入 `@` 查询当前工作区目录、选择子目录和文件；版本仍为文本。选定文件用宿主 ReferenceChip 打开右侧资源预览 |
| 材料检查 | Host 检查路径、可读性、文件大小和基本结构；PDF 必须能解析、有页面且未加密；DOCX 检查压缩包中内容类型及正文 XML；Markdown 必须是非空 UTF-8 且无 NUL |
| 初始化 | 保存 UUID 身份、材料、版本、同版声明和资源快照；临时文件同步后独占发布清单，不覆盖已有身份；成功后进入流程准备页，不启动条目化 |
| P01 摘要 | 显示真实项目、登记版本、正式基线、材料及已登记成果数量；展示资源路径、检查时间、字节数、SHA-256 和状态 |
| 资源刷新 | 重新读取已登记资源，区分有效、未校验、丢失、不可读、格式无效、超限、变化及不安全路径；刷新不改写原始快照或材料 |
| 重新关联 | 展示新旧工作区 ID、目录、修订号和未终结运行状态；必须勾选核对，服务端核对预期修订，拒绝过期确认和未终结运行 |
| 生命周期 | 唯一项目绑定、复制身份冲突、嵌套项目阻断、目录缺失与越界拒绝；已发布清单但绑定失败可刷新后恢复绑定；同 ID 工作区移动后不展示旧目录的缓存结果 |

这里只检查文件基本结构，不证明文档语义正确或原文与 Markdown 确实同版，也不运行 MinerU。已有成果只读取清单中明确登记的路径，标为未校验，不扫描或采用目录中的业务产物。已保存指纹的文件发生变化时优先显示“变化”；变更后的文件不能据此视为有效。DOCX 点击后是否可内嵌预览由宿主格式支持决定，插件不提供 DOCX 转换器。

## 调用链、配置和数据兼容

`MaterialsForm / ProjectPanel → WorkbenchData → workbench/command → owner-only WorkbenchProjects → ProjectService → WorkspaceRegistry / storageDomain / 工作区文件`。P01 的 ProjectSummary 使用同一真实响应，文件预览通过当前 Session 的 `sessionFileAddress` 与 `tab.actions.openResource` 交给宿主。业务执行器能力保持不可用，demo 不写真实项目。

项目文件为工作区 `.workbench/project.json`；绑定记录在 Host 的 `sidebar_workbench` storage domain。清单沿用 schema 1，新增可选 `resources` 快照字段：新版本能读取没有该字段的旧清单，并提示缺少原始指纹；旧版本严格解析器不保证读取新增字段，不能将降级视为支持路径。没有修改 Session 持久化事件或 SQLite schema。更新后应一起重启 Host、刷新 Client，旧的 discover/adopt 请求已被拒绝；relink 请求现在需要 `expectedRevision`。

插件 `config` 可设 `maxMaterialBytes`（默认 67108864）、`maxDocumentXmlBytes`（默认 16777216，DOCX 每个选定 XML）、`maxProjectScanEntries`（默认 100000）；均为正整数，配置错误启动时失败。后者限制嵌套项目检查的目录项数量，超限阻止初始化。初始化发布要求文件系统支持同目录硬链接；不支持时返回存储失败，不退化为覆盖写入。异常中断可能留下无引用临时文件，清单发布后的绑定失败可单独恢复。

## 人工验收准备

使用可丢弃的独立工作区和材料副本，准备同版 PDF 或 DOCX 与 MinerU Markdown，不要在唯一原件上进行删除/修改测试。源码链接开发环境在插件目录执行以下命令，然后停止并重启使用本插件的 Host、刷新浏览器；安装 tarball 的环境需重新打包并安装更新，单独刷新不能更新 Host 模块。

```powershell
Set-Location E:/dsh-sidebar-workbench
pnpm install
pnpm run build
pnpm run build:check
```

已有源码链接 profile 的启动示例（不要重建或覆盖已有 profile）：

```powershell
Set-Location E:/deepseek-harness
pnpm dsh --profile sidebar-workbench-dev --patch apps/web/tests/pin-browse-picker.overlay.yml --port 3182 --no-open
```

## 本次新增内容的人工核验步骤

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| M01 正常初始化 | 在全新工作区通过两个 `@` 输入选择有效同版材料，填写 V1，勾选同版声明并初始化；分别用 PDF 与 DOCX 在不同工作区验证 | 进入流程准备页；项目 ID、V1、真实路径显示；清单 materials 非空、baseline 为 null，resources 含两个文件；没有识别已有成果入口 |
| M02 指纹与预览 | 用 `Get-FileHash -Algorithm SHA256 -LiteralPath '材料绝对路径'` 核对两份材料，点击资源链接 | 页面与清单指纹匹配（忽略大小写），文件字节数匹配；宿主打开对应文件或其明确的不支持提示；点击不会提交或更改项目 |
| M03 格式拒绝 | 新工作区使用文本伪装 PDF、空 Markdown，逐次初始化；改用真实材料后重试 | 失败显示材料与资源状态，不生成 project.json、不创建新项目；修正后能初始化 |
| M04 刷新与重启 | 记录身份和材料，刷新页面并重启 Host；同工作区打开第二个 Session；更改工作区显示名称 | 身份、材料、版本、指纹保持一致；改名不创建项目；会话草稿互不覆盖 |
| M05 文件变化 | 初始化后修改材料副本，刷新；再移走其中一份并刷新，最后恢复初始化时原件 | 分别显示变化和丢失；缺失资源不能打开；清单原指纹不被刷新覆盖；恢复后重新检查状态 |
| M06 重新登记/迁移 | 移除工作区登记后重新登记同一目录，或在受控环境迁移目录并重新登记，确保旧登记已移除 | 显示旧/新工作区与路径、修订；未勾选不能提交；确认后修订递增，刷新不重复要求重新关联 |
| M07 复制身份 | 保留原工作区有效绑定，将整个项目副本登记为另一个工作区 | 报身份冲突，不自动接管，不覆盖任一清单 |
| M08 嵌套项目 | 在已初始化目录下创建子工作区并初始化；另用包含深层已初始化项目的父目录尝试初始化 | 两种情况均拒绝，不产生第二个嵌套清单 |
| M09 丢失与越界 | 移走工作区目录后刷新；独立测试工作区输入 ../ 路径或工作区外绝对路径 | 明确拒绝，源文件及绑定不被静默替换；恢复目录后可刷新核对 |
| M10 准备状态 | 查看流程概览、材料摘要和后续业务按钮，切换工作区再刷新 | 只显示当前工作区项目；未接入的真实业务不能启动；初始化不宣称建模或条目化完成 |

可选异常复核：通过 plugin config 降低文件限制验证超限后修正配置可重试；旧无 resources 清单显示指纹提示。部分绑定写入失败、过期修订、未终结运行阻断已有自动回归，本阶段没有真实业务入口来人工制造运行；真实运行期间的生命周期核验归阶段 4。不要手工损坏日常 Host 存储来制造异常。
