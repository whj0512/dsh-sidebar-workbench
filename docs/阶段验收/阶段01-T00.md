## 3. 接入决策与缺口

沿用一个 Workspace 对应一个建模项目，根目录只取 `Workspace.path`，当前 Session 的归属只由 `sessionIds` 精确成员关系确定。页面通过公开 Slot/actions 展示及导航，Host 通过 Remote 和独立 storage domain 管理事实，无需修改宿主核心。此阶段仅核对和提出接入建议，没有实现新通道。

后续实施按原阶段分工进行：阶段 2 复验当前 UI 和生命周期；阶段 3 补齐仍为摘要的条目/差异/映射/关系等交互；阶段 4 修正页面到编排的审核前置条件、启动幂等和可配置并发；阶段 5 验证项目与目录生命周期；阶段 6 接通 Host Run 与 Client 及恢复；阶段 7 补齐资源和权限；阶段 8 完成联合验证及文档/声明产物整理。具体源码和最小建议集中维护在[接入缺口表](../接入核验.md#4-缺口与最小接入建议)。

当前未发现必须新增宿主扩展点的确定阻塞。资源预览、Session 创建和通用重连流已有公共入口，但插件尚未接通，不等于端到端可用。下载尚未确定完整集成方式；阶段 7 先验证经授权的 bytes 读取、大小限制和用户文件保存，再决定是否需要最小扩展。任务恢复必须通过实际执行者核对，不能将 `RunService.recover()` 或重新创建实例等同于真实任务恢复。

真实执行器仍不可用，生产启动必须保持禁用。现有 demo 只用于交互与规则验证；本阶段不调用手册所述业务角色，不生成 DSL/测试/TTL，也不访问 GraphDB。

## 4. 后续隔离验证环境

以下是阶段 2 及之后的待执行方案。本阶段未创建这些目录、初始化 profile 或启动服务；采用前检查路径不存在或属于本次验证，不覆盖已有目录。实际命令和结果由执行阶段记录，不将此方案当作已验证的启动教程。

| 项目 | 隔离方案 |
| --- | --- |
| 证据根目录 | 插件忽略目录 `artifacts/acceptance-2026-10-29/` 下分阶段建独立子目录；若已有同名目录，新增唯一后缀，保留旧证据 |
| Harness home | 证据目录内新建 `dsh-home/`；仅对验证进程设置 `DSH_HOME`，结束后恢复环境。不要复用或复制用户默认 home/profile 配置 |
| profile | 在独立 home 使用 sidebar-workbench-acceptance；仅当目标 profile 尚不存在时从 web 模板初始化，再链接本插件。先核实 bundle 解析及未使用用户数据，不能对既有 profile 使用重置式初始化 |
| Host 启动 | 只通过 `pnpm dsh --profile ...`；自动化附加宿主 [pin-browse-picker overlay](../../../deepseek-harness/apps/web/tests/pin-browse-picker.overlay.yml)，选择未占用端口，仅管理本阶段创建的进程 |
| 浏览器工作区 | 使用唯一夹具目录及伪材料，不引用用户项目。当前 [browser-smoke](../../scripts/browser-smoke.mjs)会创建工作区/Session、写入夹具并初始化项目，不是只读脚本 |
| 截图输出 | 脚本把输出写到进程 cwd 下的 artifacts；先安排隔离测试工作目录，或在执行阶段增加明确的输出目录支持，不能覆盖已有同名历史截图 |
| 恢复测试 | 阶段 6 在该独立 home 使用测试专用执行适配器与可识别运行；分别记录页面关闭、断连、Host 重启和卸载，不在用户真实项目开启适配器 |

| token 与清理 | URL 通过临时环境传给测试，不进入文档、截图或提交。只释放本次连接/进程；持久化夹具保留供用户复核，人工验收前不递归清理 |

这种隔离不改变真实执行能力：没有适配器的生产模式继续不可执行；测试适配器结果统一标记“真实 Host + 测试适配器”，不写成真实业务通过。既有默认 profile 仅已核对链接，后续不将其作为自动化写入目标。
