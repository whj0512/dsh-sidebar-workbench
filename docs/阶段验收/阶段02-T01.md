| 问题与触发步骤 | 原因 | 当前行为与源码 |
| --- | --- | --- |

| 两个窗格均有草稿，关闭第二个标签页，再清空第一个，页面仍认为存在未保存草稿 | [DraftGuard](../../src/client/state/draft-guard.ts)原来只按输入更新 dirty 集合，没有跟随标签页记录删除 | 通过公开 `tab.signal` 移除已关闭标签页的 dirty 标记；侧栏折叠、Session 切换和组件卸载不清空仍存活标签页的草稿。插件卸载释放 beforeunload 及 abort 监听 |
| 首次启动冒烟等待弹窗消失时超时 | 泛化的 dialog locator 从前一个已关闭弹窗重新匹配到后一个启动提示 | [browser-harness](../../scripts/browser-harness.mjs)按弹窗名称等待关闭；明确选择测试语言，避免 profile 中上次语言设置影响后续运行 |

## 4. 人工审核步骤

先在单独终端启动本阶段的现有隔离 profile；以下命令不重置 profile。打开终端输出的本机链接，访问令牌只在本机使用，不放入反馈、截图或提交。

```powershell
Set-Location E:\deepseek-harness
$stageReviewPreviousHome = $env:DSH_HOME
try {
  $env:DSH_HOME = 'E:\dsh-sidebar-workbench\artifacts\acceptance-2026-10-29\stage02\dsh-home'
  pnpm dsh --profile sidebar-workbench-acceptance --patch apps/web/tests/pin-browse-picker.overlay.yml --port 3097 --no-open
} finally {
  $env:DSH_HOME = $stageReviewPreviousHome
}
```

1. 在宿主选择本报告截图中的测试工作区或新建隔离目录的工作区，展开右侧栏，从“开始”进入工作台。核对四个一级视图、更多四个目标、工作区目录只读和生产能力未接入提示。
2. 进入模型，选择 Statechart 并输入一段草稿。切换语言、缩窄窗口、折叠/展开侧栏，确认草稿和选择保留；用 Tab/方向键/Escape 检查焦点和菜单。
3. 分栏并在另一窗格打开工作台，选择 DialogMap、输入不同草稿。确认两边独立；关闭第二个工作台标签页并清空第一个草稿，确认浏览器不再误认为第二份草稿仍未保存。
4. 再输入 A 草稿，切到另一个工作区的会话并输入 B 草稿，再回 A，确认恢复 A 的内容，B 不覆盖 A。宿主会复用各工作区的空白会话，不将其误当作两个独立 Session。
5. 切到演示模式，从“功能与批量运行”发起完整建模，推进一个阶段，取消运行并确认停止。返回工作区模式，确认没有生产执行能力被开放。
6. **浏览器原生离开提示单独人工检查：** 保持非空草稿，尝试刷新/关闭浏览器页面，观察是否出现原生提醒并选择留在页面；清空所有仍存活标签页的草稿后再试。自动用例仅验证事件被 preventDefault，不替代此项人工结果。
