默认 Harness home 为 `C:/Users/whj0512/.dsh`，当前进程未设置 `DSH_HOME`。既有 `sidebar-workbench-dev` profile 的插件依赖为 `link:E:/dsh-sidebar-workbench`，其模块真实目录也是当前插件目录。profile 声明 base、web-app 和工作台三个 bundle；base/web-app 按 CLI 安装锚点解析到相邻宿主的对应 bundle，版本均为 `0.2.1-rc.3`。这些是磁盘解析结果，本轮没有启动或探测既有 Host，不能据此认定某个端口上的进程正在运行当前构建。

## 3. 当前调用链

项目链路为：`ProjectPanel/MaterialsForm` → Slot 注入的 `project` → `WorkbenchData.project(sessionId, action, fields)` → `ctx.remote.workbench.command` → Gateway/严格 codec → `WorkbenchProjects.command` 的 owner 检查 → `ProjectService.execute` → `workspaceRegistry` 成员与目录检查 → `.workbench/project.json` 和 binding 表。项目命令目前支持 inspect、initialize、discover、adopt、relink；这里的 adopt 是成果识别登记，不是条目版本审核采用。

demo 链路为：`Workbench.launch` → `WorkbenchData.start` → 内存 `DemoExecutor` → `data.source(sessionId)` → Slot hooks → 页面。`advance/grant/cancel/confirmCancel/reconcile/accept/retry` 都作用于此内存执行器；accept 更新的 demo 基线也在内存中。关闭正文重挂载可保留同一数据对象，浏览器刷新无法恢复此执行器；页面运行列表不读取 Host runs 表。

Host 另行执行：插件 `apply` → 打开 storage domain → 创建 `RunService` → `recover()` → 创建项目服务及 Remote。`RunService` 有内部 start/update/unsettled/recover/close 方法，但执行能力回调固定为 false，且没有对 Client 的运行读取/控制方法或真实适配器。其单元测试用内存 repository，不能作为实际存储落盘、重启或页面恢复的证明。

这些是插件接入或验证缺口，不是已证实的宿主 API 缺陷。若后续验证发现公开 API 无法满足要求，再提交具体宿主扩展建议；当前不修改宿主。

| 缺口 | 源码证据 | 最小处理及负责阶段 |
| --- | --- | --- |
| 当前 UI 的真实 Host 证据 | [阶段 2 报告](阶段验收/阶段02-T01.md)已补充当前构建下的导航、草稿、语言/主题、宽度、菜单和焦点证据；修复 Session scope 释放导致的视图丢失 | 阶段 2 待人工审核；原生提示的人工作用与读屏未实测，真实 Gateway 热卸载和 Host Run 生命周期仍留后续 |
| 场景页面仍有摘要替代详情 | [Workbench](../src/client/Workbench.tsx)、[ModelsPanel](../src/client/models/ModelsPanel.tsx)中存在固定示例文字；测试页缺逐条覆盖表，图谱缺可选择的关系列表，差异页未展示逐项匹配/采用 | 阶段 3 用结构化 demo 夹具补齐交互，不实现业务算法 |
