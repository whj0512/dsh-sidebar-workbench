## 1. 执行约束

1. 工作目录为 `E:/dsh-sidebar-workbench`。源码、测试、业务文档在本插件内实现；`E:/deepseek-harness` 用于核对公共 API 和运行宿主，不因本插件需求直接改宿主核心。公共扩展点确实不足时，先提交具体缺口与最小扩展设计。
2. 保留已有 tab ID、kind、bundle 安装方式和 Host/Client 构建分离。显示名称可调整，npm 包名不改；已有侧栏布局仍能识别工作台。
3. 每阶段先检查当前文件与已有未提交修改。保留与任务无关的内容；不得覆盖原始 PDF、项目需求、历史产物和用户已有提纲。
4. 按分阶段计划接入真实条目化、原文解析、DSL 生成/修订、测试生成、TTL 转换和 GraphDB 操作；优先复用已核验能力，补齐必要业务实现。实际执行入口、规则、配置和依赖须有证据；缺失能力不能以模拟结果代替，阶段不得据此通过。
5. 演示数据与真实项目明确隔离。模拟执行不能返回看似真实的外部回执、文件路径或模型调用成功；生产模式缺少执行器时明确禁用。
6. 不伪造宿主 API、工具名或注册服务。新增依赖时核实安装声明、构建依赖、注入和导出关系；Client 不导入其他业务插件的运行时实现。
7. 所有注册和资源都有 Cordis 生命周期所有者，store 在注册时创建，TSX 不接触 `ctx`。视图 store 只放选择、筛选、草稿等交互状态；业务事实由 Host 和 Client 领域数据层提供。
8. UI 只读校验不能代替 Host 检查。未来模型可见输入必须可由 Session 日志重建；新增 Session 事件/投影时执行对应持久化与 SDK 要求。
9. 本任务书不是部署、发布、自动上传或修改 GraphDB 的授权。操作实际数据时仍应遵守具体业务范围和手册的明确授权要求。
10. 遵守整体方案 2.3、7.4、8.3 的一对一绑定和生命周期规则。未初始化工作区可无项目，初始化后唯一绑定；不增加独立项目选择器或可编辑根目录。用户需要另一个项目时，通过 DSH 选择另一个工作区。
11. `Workspace.path`、`Session.header.cwd` 与 Session 当前工作目录分别处理。新普通执行会话通过目标 `workspaceId` 创建；功能目录作为资源位置。任务创建时固定绑定修订号和目录快照，不通过修改聊天 Session 的当前目录调度并行功能。

## 2. 建议代码归属

以下是新增文件的推荐职责，不要求一次建立所有空目录。复用已有模块后仍有独立责任时才新增文件；具体类型名称以实际实现为准。

```text
src/
  index.ts                         Host 注册与依赖声明
  shared/                          项目、运行、产物、操作与错误的共享类型
  host/
    project-service.ts             工作区唯一绑定、项目初始化、材料版本与资源检查
    run-service.ts                 生命周期、阶段依赖、调度和恢复
    artifact-service.ts            资源引用、产物清单与有效性
    execution-adapter.ts            能力声明和执行适配接口
    remote.ts                      薄 API 层，委托领域服务
  client/
    index.ts                       Slot、字典、样式与注入装配
    definition.ts                  保留工作台 id/kind 和入口
    Workbench.tsx                  页面框架
    WorkbenchTitle.tsx             侧栏标题与图标
    locales.ts                     中英文产品文字
    view-store.ts                  选择、筛选、草稿和导航状态
    data/                          宿主工作区/会话归属与插件业务数据访问
    pages/                         P00–P08 页面，按实际规模拆分
    components/                    阶段轨迹、产物与证据等插件内复用
    *.module.css                   邻近组件的局部样式
tests/
  fixtures/                      显式演示和失败场景
  ...                            组件、生命周期、编排、产物和浏览器验证
```

单一 adapter 接口的最小职责是描述能力、接受运行请求、提供阶段结果与产物、响应取消和核对中断任务。不要把所有工具调用逻辑堆在 `Workbench.tsx`、Remote Controller 或一个巨型配置对象中。

## 3. 分阶段任务

当前阶段以[分阶段实施计划](剩余任务分阶段实施计划.md#3-阶段总表)为准，不再按技术层分别完成全部 UI、编排和 Host 接入。各页面所需的持久化、取消、恢复、权限和资源访问须随当前业务交付。

T00–T05 保留为历史报告和职责分类：T00 接入核验、T01 UI 基础、T02 页面交互、T03 编排、T04 Host 数据与资源、T05 联合验收。已完成工作和后续归属见计划中的[原任务迁移](剩余任务分阶段实施计划.md#51-原任务迁移)，不以 T 编号直接放行新阶段。

## 4. 验收矩阵

每项至少保存可重复操作步骤与结果。真实业务成功路径、文件或外部回执必须实际核验；受控夹具只用于补充异常路径，不能替代真实业务验收。A18 保留缺能力时拒绝执行的要求，不构成缺失能力的完成豁免。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 工作区初始化、材料结构检查与资源摘要 | 根目录只读继承；缺材料定位到字段；保存材料版本和指纹、不修改原文件；未验证成果显示待校验；不提供已有成果识别/采用 |
| A02 | S01 首次条目化 | 能检查概述、条目、includes 证据；审核前不可自动成为后续基线 |
| A03 | S02 更新与差异采用 | 展示新增/删除/改名/内容变化；旧版本可访问；受影响产物需更新 |
| A04 | S03 单功能完整流程 | 阶段与产物一一对应，成功后可定位模型与测试映射 |
| A05 | S03 批量部分失败 | 成功功能结果保留，失败功能可单独重跑；项目关系更新不丢失 |
| A06 | S04 关系遗漏 | 展示原文证据、关系增量与待确认项，不用共享信号推断事实 |
| A07 | S05 对齐失败 | 测试阶段被阻断，问题/修订依据/未解决项可查看；原文不变 |
| A08 | S06 测试重生 | partial/missing、旧版本校验或未覆盖断言均阻止正式生成 |
| A09 | S07 本地 TTL | 能看范围、统计、问题及文件；没有 GraphDB 网络请求 |
| A10 | S08 追加上传 | 无授权不启动；目标/指纹变更使授权失效；不夹带推理或清库 |
| A11 | S09 推理 | 核对准备状态并独立授权；结果具备指定证据字段，事实与推理可区分 |
| A12 | S10 只读查询 | 不上传、不推理、不修改仓库；空结果与请求失败是不同状态 |
| A13 | 重复点击与超时 | 同一幂等请求对应同一运行；未知结果先核对，不自动重复写入 |
| A14 | 取消与晚到结果 | 收到取消确认才终结；已提交结果如实保留；旧更新不污染新 attempt |
| A15 | 关闭、刷新、切换 Session | 视图与任务生命周期独立，恢复到正确项目/功能/运行 |
| A16 | Host 重启与插件卸载 | 未完成任务被核对；无残留订阅/注册；不出现假成功或盲目重启 |
| A17 | 主题、语言、宽度与键盘 | 浅深主题可读，中英无裁切，390px 主动作可用，焦点和草稿不丢 |
| A18 | 未接入真实能力 | 生产模式明确不可执行；演示模式有标记并与真实项目隔离 |
| A19 | 文件/范围与凭据 | Host 拒绝越权资源；日志和导出无凭据；不存在的产物不可继续消费 |
| A20 | 上传已提交但验证失败 | 提交事实与校验失败同时可见；阻止推理，不宣称已回滚 |
| A21 | 无工作区、归属尚未同步 | 不回退到最近项目或进程 cwd；分别显示导航提示和加载状态，不能错误初始化 |
| A22 | 同工作区多会话、重复/并发初始化 | 共享唯一项目与成果；草稿按会话/pane 隔离；重复请求返回同一身份，清单/绑定部分写入可核对恢复 |
| A23 | 跨工作区导航与晚到结果 | 页面跟随目标会话工作区；旧初始化/查询结果不切回旧项目；原任务目录和输出保持不变 |
| A24 | 功能执行会话与当前目录变化 | 按工作区根目录创建并归属；`cd` 不改变项目绑定、运行快照或沙盒根；无并行任务竞争修改聊天目录 |
| A25 | 工作区改名和移除 | 改名仅更新标题；移除保留文件与历史，阻止新运行/下一阶段；当前阶段按真实结果收尾 |
| A26 | 目录丢失、权限失效及路径越界 | 不建立替代目录；停止依赖步骤；Host 拒绝外部输出及 symlink/junction 越界，不仅依赖 UI 禁用 |
| A27 | 原目录重新登记与项目迁移 | 显式核对新旧工作区、项目身份和未终结任务；新运行用新绑定，旧会话和运行目录快照不被改写 |
| A28 | 复制目录、嵌套项目与身份冲突 | 重复项目 ID 不形成双重有效绑定；不扫描合并其他工作区的成果或按父子目录推断会话归属 |

## 5. 检查与交付记录

本轮只制定方案，未执行以下构建、测试或服务命令。下表是实现阶段的检查任务，脚本名已从当前插件 `package.json` 核对；实际执行前再次核对版本和依赖，报告实际运行的命令及退出结果。

| 检查 | 工作目录与当前入口 | 用途 |
|---|---|---|
| 插件构建 | 插件目录，`pnpm run build` | Host/Client 产物构建 |
| 插件构建后检查 | 插件目录，`pnpm run build:check`，紧随最新 build | 当前源码、测试与构建配置类型检查 |
| 插件测试 | 插件目录，`pnpm test` | 组件、生命周期及新增聚焦编排用例 |
| 产物验证 | 插件目录，`pnpm run test:artifact` | 实际输出可加载、模块请求及公共导出正确 |
| 浏览器验证 | 插件目录，`pnpm run test:browser` | 需先按 README 准备宿主、profile 与测试 URL，并扩展旧计数器场景 |

宿主启动沿用[插件 README](../README.md)的 `dsh` profile 流程；浏览器自动化使用仓库要求的 `apps/web/tests/pin-browse-picker.overlay.yml`。新测试命令需随实现写入插件脚本；本方案不把未创建的脚本当作现有命令。

只修改插件时，运行插件范围检查；触及宿主源码才按其 AGENTS 和 pre-push skill 选择相关检查，并遵守最新 `build:artifacts` 后运行 `build:check` 的要求。文档门禁应覆盖实际被修改的文档树；宿主 `doc-sync` 不应被当成已检查外部插件文档的证据。各页面阶段的真实 API 验证属于该阶段验收范围，具体数据写入仍须按操作授权；不默认运行宿主全仓覆盖率、打包发布或推送。

交付记录必须分别列出：实现文件、已支持页面/操作、模拟验证、真实 Host 验证、真实业务验证、未验证限制。页面和真实业务均满足阶段标准后才提交人工审核；业务未接入时保持未通过，不将“外壳与编排完成”作为替代标准。

## 6. 可直接使用的 Agent 指令

```text
请在 E:/dsh-sidebar-workbench 按 docs/剩余任务分阶段实施计划.md 执行用户明确启动的当前阶段。
先阅读该计划、使用手册.pdf、三条流水线集成方案.md、三条流水线-界面与交互规范.md 和本任务书，以及适用 AGENTS.md。
阶段 1–2 已通过；后续按页面交付真实业务，每阶段（包括 9.1–9.3）完成后停止，等待用户人工审核。没有明确启动指令时不开始实施。
所有源码变更限制在插件目录，宿主仓库仅用于 API 核对与运行验证。
一个 DSH 工作区对应一个建模项目，根目录从 Workspace.path 解析；未初始化时引导填写材料和版本，在当前工作区初始化。
工作台跟随当前 Session 的工作区归属，不创建独立项目选择器或任意输出根目录；复用宿主工作区管理。
固定运行的工作区/项目、绑定修订号和目录快照，处理改名、移除、目录丢失与重新关联；切换会话和 cd 不改变已启动任务的目录。
保留现有 sidebar tab id/kind 和安装方式；使用 DSH Slot、typed locale、CSS Modules 与现有 UI primitives。
按当前阶段接入真实业务执行器，补齐必需的页面、Host、持久化、恢复、权限、资源访问与业务实现；不提前实施后续阶段。
未接入的操作保持禁用，演示数据与真实项目隔离；当前阶段必需能力缺失时记录阻塞，不用 demo 或测试适配器代替真实验收。
按验收矩阵验证状态、版本、阻断、取消、恢复和授权，不得将模拟结果称为真实业务通过。
完成后更新 README 与验证记录，报告实际检查命令、结果和仍待接入的能力。
遇到宿主公共扩展点缺口时提交具体证据与最小扩展建议，不直接改 agent-loop 或内部 dockkit。
```
